# Benchmark Results

This directory holds output generated by local benchmark runs. Saved reference data are stored
in [`content/`](../content/), and images are stored in [`figures/`](../figures/). See [Benchmarks](../content/Benchmarks.md) for methodology
and caveats.

## Generated N-Queens Results

[`nqueens_results`](nqueens_results) is written by
[`NQuenensBenchmark`](../src/main/java/application/nqueens/NQuenensBenchmark.java).
It runs N = 8 through 12 for the plain BDD solver and for NDD with BDD, complemented-BDD,
and ZDD label modes. Each section reports `N`, `Time (s)`, `SatCount`, and `Nodes`.
The same results are printed to standard output as each run finishes.

Run these commands from the repository root:

```bash
mvn -DskipTests package
java -cp target/ndd-1.0.1-jar-with-dependencies.jar application.nqueens.NQuenensBenchmark
```

Each run overwrites `results/nqueens_results`. An existing file reflects its last run;
rerun the benchmark to generate output with the current code and settings.

## Saved Reference Results

These artifacts are preserved benchmark data, rather than files generated by the current
benchmark commands.

### N-Queens

Cross-library comparison on N-Queens for N = 8 to 13. Documentation:
[Results: NQueens](../content/Results-NQueens.md).

The saved cross-library CSV is stored in [`content/nqueens_metrics.csv`](../content/nqueens_metrics.csv);
the Java benchmarks emit metrics to standard output rather than writing this CSV.
Plots are stored in [`figures/`](../figures/).

| File | Content |
| --- | --- |
| [`nqueens_metrics.csv`](../content/nqueens_metrics.csv) | One row per implementation and board size |
| [`nqueens_time_sec.png`](../figures/nqueens_time_sec.png), [`nqueens_time_sec_log.png`](../figures/nqueens_time_sec_log.png) | Running time (linear and log scale) |
| [`nqueens_max_rss_kb.png`](../figures/nqueens_max_rss_kb.png), [`nqueens_max_rss_kb_log.png`](../figures/nqueens_max_rss_kb_log.png) | Peak memory (linear and log scale) |
| [`nqueens_nodes_created.png`](../figures/nqueens_nodes_created.png) | Total nodes created |
| [`nqueens_nodes_alive.png`](../figures/nqueens_nodes_alive.png) | Nodes alive |

CSV columns:

- `implementation`, `language`, `size` (N)
- `time_sec`: running time in seconds; BuDDy at N = 13 hit the 500 s limit
- `max_rss_kb`: peak resident memory in KB
- `nodes_created`, `nodes_alive`: total nodes; for NDD, the sum of NDD nodes and label BDD nodes
- `ndd_nodes_created`, `ndd_nodes_alive`, `bdd_nodes_created`, `bdd_nodes_alive`: the NDD and BDD parts
- `solutions`: number of solutions, identical across implementations (0 for runs that timed out)

Implementations: `NDD` is the current library on the `main` branch, and `NDD-Origin` is the original
NDD prototype.
The others are BDD libraries: BuDDy, CUDD, JDD, JavaBDD, JavaBDD-C, [DecisionDiagrams](https://github.com/microsoft/DecisionDiagrams) (BDDNode) and
DecisionDiagrams (CBDDNode) (named `DD-BDD` and `DD-CBDD` in the CSV and plots), and JSylvan.
JSylvan is a parallel library and was run with 48 worker threads; all other implementations are
single-threaded.

To run only the NDD solver for selected board sizes, build the project and run
[`NDDSolution`](../src/main/java/application/nqueens/NDDSolution.java):

```bash
mvn -DskipTests package
java -cp target/ndd-1.0.1-jar-with-dependencies.jar application.nqueens.NDDSolution 8 9 10 11 12
```

This prints `NQUEENS_METRICS` lines to standard output. Add `--bcdd` or `--zdd` before the
board sizes to select another label backend; the default is BDD labels.

The other libraries are benchmarked in the companion repository
[nqueensBenchmarkDDs](https://github.com/XJTU-NetVerify/nqueensBenchmarkDDs).

### SRE (network verification)

Network-verification workloads on BGP fattree networks (`bgp_fattree04` to `bgp_fattree20`), each
with `MF` = 1 to 3, using a 14,400 s timeout per variant. Documentation:
[Results: SRE](../content/Results-SRE.md).

| File | Content |
| --- | --- |
| [`SRE_results`](../content/SRE_results) | One table per dataset and `MF` value |

Variant names in `SRE_results` differ from those used in the documentation:

| In `SRE_results` | In the documentation | Meaning |
| --- | --- | --- |
| `bdd` | `bdd` | Plain BDD baseline |
| `ndd` | `NDD-Origin` | Original NDD prototype |
| `ndd-reuse` | `NDD-Reuse` | NDD with label-variable reuse across fields |
| `ndd-array` | `NDD` | Current NDD with the array-based node table |

Columns: `src(s)` is the source-stage time, `total(s)` the total running time, `peak rss` the peak
resident memory, `bgp routes` the number of routes in the input, and `bdd nodes` the size of the
BDD label layer.

No script that generates `content/SRE_results` is included in this repository.
The SRE drivers depend on external datasets and are not part of the default Maven build.
